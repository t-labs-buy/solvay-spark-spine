Part 1 · Agent architecture and orchestration

How the agents are built

Asked by — architects, developers

1. What framework, SDK or design pattern did you use to build the agent pipeline? Why not LangChain, LangGraph or CrewAI?

Say first: No agent framework. Each agent is a small tool-use loop written directly on the Anthropic Python SDK, with Pydantic schemas for the output and plain Python for everything that must be deterministic.

There are four model-calling components, and each uses the pattern that fits its job:

ComponentPatternCode
Ask RAGRetrieve → generate with citations (no agent loop)rag.py
Evidence AgentSingle ReAct-style tool loop over the corpus and the graph, then a deterministic verifier and scorerevidence/
InsightLensMap-reduce: one bounded agent run per BPML step, several in parallel on a thread pool, then one synthesis passbackend/agents/fitgap/orchestrator.py
Fit-Gap CopilotTwo-pass pipeline: Read (attachments only) → Compare (corpus + graph + BPML), then deterministic gates and scoringbackend/agents/rollout/orchestrator.py

The agent submits its result through a tool (submit_entry) whose input schema is the Pydantic model, so malformed output is rejected at the boundary instead of being parsed afterwards.

If they push on "why no framework"

The value here is in the parts that aren't the loop: the verifier, the score arithmetic, the quality gates, the budgets. A framework would own the loop and leave those just as hard to write, plus a dependency whose abstractions change every quarter. The loop is about a hundred lines, fully traced in Langfuse, and each turn is inspectable. If the team later needs durable, resumable multi-agent workflows, LangGraph or the Claude Agent SDK could replace the loop without touching the verifier or the scoring.

2. How do the agents interact with the RAG system and the knowledge graph? What tools and APIs do they call?

Say first: Through a small set of typed tools. The model never runs SQL or graph queries itself. It asks for a search, and our code runs it and records what came back.

ToolWhat it doesBacked by
search_corpusHybrid vector + keyword search, optional category filterpgvector + Postgres full text

Every call is logged to session.retrieved. That record is what the verifier later checks quotes against (Q4), which is why routing everything through tools matters.

3. How is orchestration handled: concurrency, failure, long runs?

Say first: Runs stream events to the browser as they happen, work in parallel where the steps are independent, and are written to Postgres as they go, so an interrupted run keeps what it had done.

  • Streaming: Server-Sent Events. The register fills in row by row instead of showing a spinner.
  • Parallelism: InsightLens runs N BPML steps at once on a thread pool (the concurrency is a request parameter).
  • Cost preview: before a run starts, preview() shows the steps it will cover and an estimated token count, so the cost is visible before the button is pressed.
  • Durability: runs are persisted incrementally. A closed tab leaves a run marked abandoned after 30 minutes, with its tool calls kept. Failed runs are kept too.
  • Budgets: the loop stops on its tool-call limit, its per-turn context limit, or 4× that cumulatively, and the trace says which one stopped it.
The one-line version

Plain SDK loops plus deterministic code, not a framework. Retrieval and graph access only through typed, logged tools. Parallel where the work allows it, streamed and persisted as it happens.

Part 2 · Guardrails and governance

Guardrails, verification and human control

Asked by — architects, risk & compliance, PMO

4. What guardrails have been implemented for the agent ecosystem?

Say first: Guardrails at four layers: before a run, during it, on what comes out, and a person at the end. Each one is enforced in code; the prompt repeats the rules only as a second line of defence. The model proposes; deterministic checks decide what survives.

LayerGuardrailHow it is enforced

Programme terms (a BPML code, ticket, system name) pass instantly; anything else goes to a small classifier model. Out of scope: "I don't have the information.", with nothing searched and nothing scored.
During the runEvidence only from tools. "Never output a ticket, BPML code or system name no tool returned." "Prefer UNKNOWN over a low-evidence guess."Quote verification (below). A rubric hash is stored on every run so results can be reproduced.

The corpus must already have been searched in this run; at most 2 searches; only sap.com and europa.eu; the query must be on-topic, with no ticket numbers, BPML codes or contact details. Web quotes are verified like any other, and a claim resting on web pages alone is capped at 0.35.
During the runBudgets.Hard caps on tool calls and input tokens per run, so a runaway loop can't run up cost.
During the runIsolation.Session uploads live in their own database and are deleted after 12 h. Memory can orient an agent but can never be cited (Q13).

Show it live instead of describing it

In Ask RAG, type "Write a poem". It answers "I don't have the information." in about two seconds. The pipeline panel shows nothing was searched, and the Quality panel says it wasn't scored. Then ask a real programme question to show the contrast. It lands better than any slide.

The three follow-ups a reviewer will ask, and the honest answers
  • "What if the scope classifier is down?" The question goes through, and the run log records that the filter was unavailable. The agents' own instructions still tell them to refuse. We chose this over blocking every question during an outage; it can be switched to refuse instead.
  • "Can it be tricked?" A borderline question can get past a classifier; that's why it is one layer, not the only one. Whatever gets through still has to be answered from verified quotes in the programme's own documents, or it isn't shown.
  • "Are you sure it never shows a phone number?" We measured the corpus: 116 e-mail addresses and 21 phone numbers are removed. SAP order numbers, BPML codes, dates and amounts are deliberately left alone, and each of those is a regression test. A number written with no phone-like formatting and no "Tel:" label nearby would get through; say that rather than "never".

5. (Skeptical) LLMs hallucinate. How can I trust that a citation is real and not invented?

Say first: You don't have to trust the model. A citation is only shown if our code found the quoted text inside the chunk it names, and only if that chunk was retrieved in this run. Anything else is deleted before display.

The match allows for how people copy text (curly quotes, collapsed spaces, table pipes) but not for paraphrase. Each claim's support score starts at 0.50 for one passage and adds 0.15 per further independent document; near-duplicate copies don't count twice. It loses 0.25 if a retrieved passage contradicts it and is capped at 0.40 when the only support is an email, minutes or a transcript: discussion, not implemented state.

What to concede

A verified quote proves the source says that. It does not prove the model drew the right conclusion from it. That is why the Fit-Gap gates deliberately skip QG3 (semantic accuracy) and say so, and why a person makes the final call (Q6).

6. Who is accountable for a decision? Is there a human in the loop?

Say first: Yes, by design. AI proposes, humans decide. Every InsightLens entry is created with status = "proposed" and waits for a named reviewer. Fit-Gap deviations are framed as decision questions for a workshop, not as recommendations.

The rubric forbids the model to recommend what the client should decide: it must frame the choice as a DecisionPoint. Reviews and decisions are stored in their own tables (fitgap_reviews, rollout_decisions), so the audit trail shows who accepted what, and when.

Part 3 · RAG architecture

Retrieval-augmented generation

Asked by — architects, developers

7. Walk us through the RAG architecture, from a PowerPoint to a cited answer.

Say first: Docling converts the document to Markdown. We split it along its headings, embed it locally, store it in Postgres, and search it two ways. Claude answers from the best excerpts and cites each one.

Ingest
Docling + OCRPPTX, DOCX, XLSX, PDF, images → Markdown. Tesseract, OpenCV table and flow detection, optional vision model
Markdown
Index
Chunk + embedHeading-aware chunks of ~500 tokens (max 1,000), title and heading path added; BGE-M3 on Ollama
vectors + text
Retrieve
Hybrid searchpgvector HNSW cosine + BM25 full text, merged by RRF (1 / (60 + rank))
top k
Generate
ClaudeAnswers only from the excerpts, cites them, streams to the page; the answer is then judged by Ragas in the background

Two design choices worth mentioning:

  • Why hybrid: embeddings treat identifiers like 7.1.12.3 or M-090-030-010 as noise. Keyword search catches them, and codes are indexed with their parent codes as well. On the one code question in the demo set, vector search ranked the right row 8th and hybrid ranked it 2nd.
  • Category is metadata, not embedded text. Re-filing a document is one SQL UPDATE, not a re-embedding.

8. Why pgvector and not a dedicated vector database such as Pinecone, Weaviate or Qdrant?

Say first: Because the text, the vectors, the full-text index, the categories and the agent run history all live in one transactional database. Hybrid search is a single query, and deleting a document deletes its chunks through a foreign key.

At ~9k chunks, pgvector's HNSW index answers in milliseconds with 0.98 recall. A dedicated vector store would add a second system to secure, back up and keep in sync, with no gain at this scale. It becomes worth revisiting in the tens of millions of vectors, or if many tenants each need their own index.

Part 4 · RAG evaluation and quality metrics

How we know the answers are good

Asked by — tech leads, product owners, QA

9. What evaluation framework and metrics do you use for the RAG system?

Say first: Ragas, with Claude Sonnet as the judge. Every live answer is scored automatically in the background on twelve metrics. The scores are stored with the answer, sent to Langfuse, and shown on the page and in a Quality workspace.

GroupMetricsWeight in overall
GenerationFaithfulness, Answer relevancy0.30, 0.20
RetrievalContext precision, Context relevance, Context utilization0.15, 0.10, 0.10
StyleCoherence, Conciseness0.10, 0.05
SafetyHarmfulness, Maliciousness (toxicity and bias optional)A flag caps overall at 0.25
Offline onlyAnswer correctness, Context recallneed a reference answer: run over the 27 ground-truthed questions

Faithfulness carries the most weight because unsupported claims are the most damaging failure for this kind of corpus. A judge that times out is left out and the other weights are rescaled. It is never counted as zero. Clicking any metric shows the judge's reasoning, for example each claim with its verdict, or each excerpt with its relevance.

10. (Skeptical) You're using an LLM to grade an LLM. Why should I believe the scores?

Say first: You shouldn't, until they've been checked against people, and the product says so on every page. We measure how much the judge can be trusted instead of assuming it.

  • Against people: reviewers mark answers Grounded / Partly / Not grounded. Cohen's kappa is reported once 20 reviews exist. Today there are 0, and the UI shows a banner saying the scores are unverified.
  • Against itself: re-scoring the same answer moves it ±0.01–0.04, so differences under ~0.05 are treated as noise.
  • A known bias we found: 18 of 76 "unsupported claims" were the answer describing its own sources, which the prompt asks for. Faithfulness is therefore slightly understated, and we can explain exactly why.
Why this answer lands well

Senior reviewers are wary of AI metrics presented as facts. Naming the calibration gap and the known bias yourself shows the numbers are being handled critically, which is worth more than a high score.

Part 5 · GraphRAG and the knowledge graph

Knowledge graph construction and maintenance

Asked by — architects, data engineers

11. How is the knowledge graph built from the Markdown files, including entity and relationship extraction?

Say first: Without a language model. Extraction is deterministic: patterns and structure-aware parsing over the Markdown. The same input always produces the same graph, which a test checks.

EntityHow it is recognisedCount
Process (BPML)Code patterns such as O-020-090, plus the BPML hierarchy parsed from the workbook1,985
DocumentEvery indexed Markdown file, carrying its category217
Spec / ticketSPARK-\d{4,6}, and rows of the specification register165
SystemA curated dictionary: S/4HANA, ECC, Salesforce, SOVOS, Fiori, CPI, EWM, GTS, MDG, …18
StreamL2C, I2D, R2R, P2P4

Relationships come from co-occurrence within a document and from structure: specifies_process (1,947), subprocess_of (1,846), mentions_system (556), belongs_to, references_ticket and implements_ticket — six types, each carrying the rule that made it and the chunks it came from. A passage layer links 8,867 chunks to the entities they name. Queries use in-memory breadth-first search for paths and a 2-hop "bridge" expansion to get from a platform, through an interface spec, to its tickets.

If asked "why not let an LLM extract the graph?"

An LLM-built graph is different on every rebuild and can invent relationships nobody can trace. Here every edge can be traced to a line in a document. The trade-off is recall: a relationship described only in prose ("the credit check calls Coface") is missed unless both names are recognised entities. A model-assisted extraction step whose output is verified against the source, the same way quotes are, is on the roadmap (Q20).

12. How is the graph kept current, and why not Neo4j?

Say first: It rebuilds automatically from the same folders the vector index reads. The cache is keyed by a SHA-256 hash of each file's content, so adding a document is enough. Neo4j would add a server with no benefit at 2–5k nodes, but the graph already exports to Neo4j.

Adding a category means creating a folder, with no code change. kg_neo4j_export.py writes the graph in Neo4j's model (PascalCase labels, SCREAMING_SNAKE relationship types) together with a Cypher schema, so migrating is an export, not a rewrite. Move to Neo4j when the graph reaches hundreds of thousands of nodes, needs concurrent writes, or has to be shared with other systems.

Part 6 · Agent memory

What the agents remember

Asked by — architects, AI engineers

13. What memory system do the agents use, and how is memory stored and retrieved?

Say first: Hindsight, an open-source agent memory server. The rule we built around it is that memory orients, it never grounds: it can tell an agent where to look first, but a remembered fact can never be cited as evidence.

  • Write (retain): only verified claims from finished investigations are stored, in the spark-evidence bank. A claim whose quotes failed verification is never stored, because nothing would re-check it later.
  • Read (recall): semantic, BM25, entity-graph and time-based search in parallel, capped at 1,200 tokens of context, with an 8-second timeout so a slow memory server can't stall a run.
  • Why it can't be cited: the verifier only accepts quotes from session.retrieved, which only retrieval tools write to. Memory content isn't there, so no prompt instruction is needed to enforce this.
  • Holdout runs (used to measure the agent) neither read nor write memory, so memory can't skew the measurement.
  • On screen: recalled notes appear in a separate panel labelled not evidence.

It is optional and fails safe. If the server is down, every memory call returns empty and the agent runs as before.

Be ready for the data-residency follow-up

Hindsight uses an LLM (Claude, via LiteLLM) to turn an investigation note into facts, so those notes leave the machine on every retain. Its launcher can use a local Ollama model instead if that is a requirement.

Part 7 · Fit-Gap Copilot

The Fit-Gap Copilot

Asked by — product owners, SAP leads, business

14. What business problem does the Fit-Gap Copilot solve, and how does it reach its scores?

Say first: It prepares an SAP Activate Fit-to-Standard analysis for a country rollout. It compares the country's As-Is documents with the Global Template and SAP Best Practice, and produces a deviation register, a localization advisory, and a workshop agenda to review.

  1. Read: sees only the attachments and builds a normalised As-Is process model, step by step, including what the documents never said.
  2. Compare: now given the corpus, graph and BPML hierarchy, it produces deviations on a 16-code taxonomy and rates seven dimensions from 0 to 4.
  3. Gates and arithmetic: the quality gates repair the output, and backend/agents/rollout/scoring.py computes the alignment scores from the rated register.

Documents are uploaded with a role (Country As-Is, Global Template, SAP Best Practice, Localization source, Reference), which is what makes a three-way comparison possible. A localization only raises the adjusted score when it is confirmed with a source. A suspected one does not.

15. (Skeptical, business) Does this replace the functional consultants? How accurate is it?

Say first: No. It replaces the first draft, not the judgement. The consultant starts from a sourced register in which every item carries a quote, instead of a blank workbook, and spends the workshop on decisions rather than on finding the documents.

On accuracy, be precise: there is a golden set (docs/spark-fitgap-eval-golden-set.xlsx) and a holdout mode that hides the fit registers to measure the agent honestly. Present results from those, not impressions. Semantic accuracy is left to a human on purpose (QG3). One real safeguard came from a failure: the first real run gave a measured-looking score over a register that said everything matched. Now a dimension rated 2 or lower must name at least one deviation.

17. What data leaves our environment, and is this production-ready from a security standpoint?

Say first: Embeddings, search and the graph run locally. The question and the retrieved excerpts go to Anthropic to write the answer, and traces go to Langfuse if it is enabled. It is a local workbench today, not a hardened service.

  • Stays local: document conversion, OCR, embeddings (BGE-M3 on Ollama), vector and keyword search, knowledge graph, and optionally the vision model (Qwen3-VL on MLX).
  • Leaves the machine: excerpts and prompts to the Anthropic API; the typed question to a small Anthropic model for the scope check, when no programme term settles it; web search queries, only when an agent's gated search runs, stripped of ticket numbers, BPML codes and contact details, and only to sap.com and europa.eu; trace content to Langfuse, where document text is not masked on purpose, so point it at a project you're allowed to show the corpus to; memory notes to Claude for fact extraction; images, if a cloud vision provider is chosen.
  • Never shown to users: e-mail addresses and phone numbers. They are removed from every answer, excerpt, history view and export, whatever the source document says.
  • Missing before a network deployment: authentication and role-based access control, upload size limits, sandboxing of the document parsers, and per-user data separation. The README lists these as the conditions for leaving localhost.
Don't overclaim here

Security reviewers will ask about SSO, encryption at rest, and whether Anthropic trains on the data. Answer from the deployment plan and your organisation's Anthropic agreement. Don't imply the current build has controls it doesn't have.

Part 9 · Traceability, explainability and observability

Explaining an answer, and watching the system

Asked by — auditors, tech leads, operations

18. If a stakeholder challenges an answer six weeks from now, can you show exactly how it was produced?

Say first: Yes. Every run is stored with its question, settings, each tool call and what it returned, the model turns and token usage, the verified answer, and a hash of the prompt that produced it. It can be reopened with nothing re-run and nothing re-billed.

  • In the product: a history panel on every page. Answers link to the exact chunks, and claims show the arithmetic behind their score.
  • In Langfuse: one trace per run, grouped into sessions per upload. Retrieval, tool, generation and evaluator spans, with cost per model call. Evaluation scores are attached to the trace, so "all answers with faithfulness below 0.7" is a filter.
  • Reproducibility: prompt and rubric hashes are stored on each run, so two runs on either side of a prompt change can't be compared by accident.
  • Quality monitoring: the Quality tab shows score trends, failures grouped by cause and subject, noisy source documents, experiment comparisons, and judge trust. A Langfuse dashboard is also kept as code in the repo.
Part 10 · Scalability, performance and cost

Scale and cost

Asked by — architects, sponsors, finance

19. How does this scale, and what does it cost to run?

Say first: Storage and retrieval scale comfortably: Postgres and pgvector handle millions of chunks. The limits are model latency and cost, and those are controlled with budgets, the choice of model per task, and caching.

What scales well today Hybrid search takes ~180 ms with 0.98 recall. Graph traversal is under 2 ms in memory. Re-indexing only re-embeds changed files, and a category migration moved vectors in ~3 s instead of 18 min of re-embedding. Embedding is local, so indexing costs nothing per token.
What would need work at enterprise scale A single FastAPI process with a thread per run; Ollama embedding throughput for bulk loads; an in-memory graph (fine to ~10⁵ nodes, then Neo4j); multiple users would need a job queue and horizontal workers.

Cost levers already in place:

  • Opus writes the answers, Sonnet judges them. Judging on Opus would cost more than answering.
  • RAG_EVAL_SAMPLE judges a fraction of traffic; the Ragas disk cache makes re-running experiments cheap.
  • Hard caps on tool calls and tokens per run, and an estimate shown before a Fit-Gap run starts.
  • The scope guardrail refuses an off-topic question for the cost of one small-model call (~2 s), with no search, no answer and no scoring. Before, "Write a poem" went through the whole pipeline and all nine judges.
  • Web search is capped at 2 per run; one search is about 19k input tokens on Sonnet, around 17 s.
  • Memory reduces repeat investigations. Measured: raising retrieval from 8 to 12 excerpts cost 40% more tokens for +0.02 overall, which is within noise, so we kept 8.
Prepare one concrete number

Sponsors will ask for "cost per question" or "cost per rollout analysis." Before the session, open Langfuse and note the median cost of an Ask trace and of one Fit-Gap run. A real number from your own traces is far more convincing than an estimate.
